# Пайплайны
Здесь можно создававать свои топологии графа, по которому будет работать агент.
Есть всего один исполняемый поток. Параллейные вызовы реализуются через специальную ноду.
После некоторых нод поток можно закольцовывать.

Карточки имеют три основных типа соединений:
Exec - определяет последовательность выполнения операций единым потоком.
Prompt - передаёт текстовые инструкции модели. Во вход prompt можно передавать множество соединений.
Arg - передаёт значения и структурированные данные между карточками. Во вход arg нельзя передавать более одного соединения.

Соединения Prompt и Arg не создают самостоятельных исполняемых потоков. Они используются для передачи данных, которые будут востребованы соответствующими карточками. Циклические зависимости между такими соединениями запрещены.
Эти соединения не обязательно подключать. Если у ноды останутся пустые Prompt и Arg, то модель просто не получит дополнительного запроса, а аргументы сгенерирует сама.

Некоторые карточки выполняют операции самостоятельно, без обращения к модели. Например, преобразование данных, выполнение Python-кода или отправка уведомления.
Другие карточки могут обращаться к основной модели, субагентам или пользователю для принятия решений, формирования аргументов и выбора дальнейшего маршрута.

Таким образом, пайплайн может сочетать заранее определённую последовательность операций с решениями, которые принимаются непосредственно во время выполнения.

Для каждой поддерживаемой исполняемой карточки можно настроить обработку ошибок: остановить выполнение, повторить операцию, пропустить её или направить поток в отдельную ветку обработки ошибки.

Также предусмотрены точки завершения. Graph End завершает текущий пайплайн и возвращает результат, а Graph Shutdown завершает весь запуск агента.
Состояние выполнения также сохраняется, что позволяет возобновлять прерванные запуски при наличии подходящей точки восстановления.

Перед выполнением пайплайн проходит проверку корректности соединений, доступности инструментов, циклических зависимостей и других ограничений. Проверку также можно запустить вручную из редактора.

Также пайплайны можно публиковать через Toshy MCP, предоставляя возможность вызывать их внешним приложениям и ИИ-агентам

## Карточки
1. Промпт - Карточка с текстом, который будет передан модели в качестве дополнительного запроса перед выполнением шага графа.
	
2. Маршрутизатор - Позволяет делать любого размера развилки и перемещаться на определенные части пайплайна. Механизм, по которому определяется маршрут, задается в настройках карточки. Позволяет закольцовывать ветки, подключая маршрутизатор назад, или наоборот, пропускать куски ветки, подключая маршрутизатор куда нибудь вперед.
	
3. Петля - Перенаправляет поток выполнения до тех пор, пока не будет выполненно условие для продолжения ветки. Позволяет задать максимальное кол-во витков. Позволяет настроить, что передавать вперед, результат только успешного витка, или всех циклов. Механизм, по которому определяется успешность витка задается в настройках карточки. Аналогично маршрутизатору позволяет передавать поток как назад, так и вперед.
	
4. Параллейные инструменты - Указывает модели одновременно вызвать сразу множество инструментов. Можно настроить как параллейное выполнение, так и последовательный вызов. Во втором случае все равно будет только один блок размышлений перед всеми вызовами, просто сами инструменты вызовутся последовательно. Также во втором случае имеет значение порядок нод. Нода вызова субагента в параллейных инструментах может быть только одна, однако из неё можно продолжать цепочку вызовов субагентов.
	
5. Human-in-loop - Останавливает граф и отправляет в чат пользователя вопрос с подтверждением. Позволяет запрашивать пользовательский ввод аргументов.
	
6. Shutdown графа - Полностью останавливает ВСЮ генерацию.
	
7. Завершение подграфа - Завершает текущий пайплайн, продолжая генерацию.
	
8. Уведомление - Отсылает в чат пользоватля уведомление и продолжает выполнение пайплайна автоматически.
	
9. Вложеный пайплайн - Стартует какой то другой пайплайн в том же модуле и ждет его завершения.
	
10. Python код - Многофункциональная нода, в которой можно делать в общем то что угодно с аргументами. Подробнее ниже.
	
11. Преобразование данных - Работа с различными форматами данных. Например извлечь дату из Json. Подробнее ниже.

13. Самостоятельное решение агента - Модель может вызвать что хочет или ничего.
	
14. Ноды аргументов содержат типизированные значения и используются для ручного определения аргументов нод.
	
По поводу карточек инструментов модулей, там в целом все стандартно, и единственное, что нужно выделить отдельно, это нода вызова субагента:
У нее два выхода. Причем первый блокируется если подключен второй, а второй можно подключить только к другой ноде вызова субагента. Второй выход необходим для создания цепочек вызовов субагентов, что бы те передали контекст друг другу, не через основного агента.

### Python код

Нода выполняет Python-скрипт и передаёт результаты только аргументами. По exec потоку ничего не передается.

В настройках добавьте входные и выходные аргументы. Каждому задайте имя и тип. Имена должны быть допустимыми именами Python-переменных и уникальными внутри соответствующего списка.

Подключите данные к входным Arg. В коде они доступны как обычные переменные с указанными именами. Недостающие входные значения система может запросить у модели.

Напишите скрипт в поле кода. Для каждого объявленного выхода присвойте значение переменной с точно таким же именем. Оборачивать скрипт в функцию не требуется; верхнеуровневый return не используется.

Выходные значения должны поддерживать JSON-сериализацию и соответствовать объявленным типам. Отсутствие значения хотя бы одного выхода считается ошибкой. print() сохраняется в отчёте выполнения, но не заменяет выходные аргументы.

Скрипт запускается отдельным процессом с рабочей папкой проекта. Во время его исполнения модель не участвует в вычислениях. Процесс имеет доступ к файлам и окружению пользователя: это не защищённая песочница.

### Преобразование данных

Нода обрабатывает входное значение последовательностью настроенных операций и передаёт результаты только аргументами. По exec потоку ничего не передается.

В настройках добавьте операции кнопкой «+». Для каждой выберите действие и заполните его параметры.
Расположите операции в нужном порядке кнопками перемещения. Каждая операция получает результат предыдущей.

Доступны операции с JSON, извлечение и переименование полей, фильтрация и сортировка массивов, удаление дубликатов, обработка текста и регулярных выражений, преобразование дат, часовых поясов и типов.

Пути к вложенным значениям задаются через точку либо в формате JSON Pointer. Элементы массива адресуются индексами с нуля. Пустой путь обозначает всё текущее значение.

Если вход содержит JSON в виде строки, включите автоматический разбор JSON перед операциями с полями или массивами либо добавьте отдельную операцию разбора JSON.
